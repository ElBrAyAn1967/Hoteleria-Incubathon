Two real exceptions: the "ghost-card" border+shadow combo on `request/page.tsx:64` and `ChatWidget.tsx:75` — ironically the exact pattern the team's own `globals.css:32` comment says to avoid.

## Overall Impression

The frontend has unusually strong *infrastructure* discipline for a hackathon build — a real design-token system, centralized copy, accessible form components — but the polish that infrastructure should produce hasn't fully landed yet: a core demo path (request → itinerary) is visually connected but not data-connected, the brand's own accent color fails contrast in its most common use, and the one screen meant to reassure the user at the highest-stakes moment (submitting a request) gives the least feedback of any screen.

## What's Working

1. **Token discipline built for re-branding.** `tailwind.config.ts` and `brand.ts` centralize identity exactly as `docs/dev/DUPLICACION.md` requires — this will pay off directly when the repo is duplicated for the second hackathon entry.
2. **Anfitriones section avoids the generic-provider-row trap.** Each host has a name, a specialty, a first-person voice — directly honors the "host is not interchangeable" product constraint.
3. **Accessible form components.** `FormField.tsx` correctly wires `useId`, `aria-invalid`, `aria-describedby` and is reused consistently across `/request` and `/feedback`.

## Priority Issues

**[P0] Itinerary page doesn't use the request the user just submitted**
- Why it matters: `/itinerary` renders a hardcoded mock itinerary instead of reading the quote saved by `/request`. A juror or user clicking through the flow twice with different answers gets the identical result both times — it breaks the core pitch ("the brain builds your route for you") the moment anyone looks closely or refreshes.
- Fix: read the stored request (`sessionStorage` key `navigox_quote`) in `itinerary/page.tsx` and reflect it, even if the "matching" is still a mock selection.
- Suggested command: `$impeccable harden`

**[P1] The brand's accent color fails contrast almost everywhere it's used as text**
- Why it matters: Oaxacan Chili Orange (`#F47C3C`) as text on the gray/white backgrounds measures 2.2–2.7:1, well under the 4.5:1 minimum. It recurs across `/home` and `/itinerary` — this isn't a one-off typo, it's a token-level defect that will keep resurfacing on every future screen that reuses the accent color for text.
- Fix: keep `#F47C3C` for buttons/backgrounds/icons (where it already has enough contrast), but darken it (or switch to `ink`) whenever it's used as text on light surfaces.
- Suggested command: `$impeccable audit` (a11y-focused pass), then `$impeccable colorize` if a darker "text-safe" accent variant needs to be added to the token set.

**[P1] The feedback success screen is a dead end**
- Why it matters: after finishing the loop, there's no link back to `/` or `/home` — a user (or a juror in a live demo) is stranded with only the browser back button, undercutting an otherwise warm, well-written thank-you message.
- Fix: add a "Volver al inicio" link/button on the success state.
- Suggested command: `$impeccable clarify`

**[P1] Ghost-card pattern (border + shadow together) on the highest-stakes screen**
- Why it matters: `request/page.tsx:64` and `ChatWidget.tsx:75` both combine a border and a soft shadow on the same card — exactly the pattern the team's own CSS comment (`globals.css:32`) calls out to avoid, and it shows up on the quote-request form, the screen meant to feel most trustworthy.
- Fix: pick one — a crisp border with no shadow, or a shadow with no border — consistent with how `.btn-primary` already does it.
- Suggested command: `$impeccable polish`

**[P2] "Usar ubicación actual" toggle doesn't do anything**
- Why it matters: it swaps a label but never calls real geolocation; a user who taps it twice, expecting their location to be captured, sees nothing happen beyond a color change and reasonably assumes it's broken.
- Fix: wire it to `navigator.geolocation.getCurrentPosition` (even with a fixed fallback), or change the copy so it's clearly a manual toggle, not a location request.
- Suggested command: `$impeccable harden`

**[P3] Hardcoded hex breaks the single-source-of-truth re-brand story**
- Why it matters: `RouteMap.tsx:23` has a literal `stroke="#1A2A44"` instead of the `ink`/`primary` token — the one spot in this review that will silently go stale the next time this repo is duplicated with a new palette.
- Fix: reference the CSS token/currentColor instead of the literal hex.
- Suggested command: `$impeccable polish`

## Persona Red Flags

**Jordan (First-Timer)**: On `/itinerary`, the header says "Mapa" while the bottom CTA for the same screen says "Itinerario" — Jordan may think these are two different things and miss that the CTA just continues the flow they're already on.

**Riley (Stress Tester)**: The budget field (`type="number"`, only a `>0` check) accepts absurd values like `999999999999` with no upper bound or formatting. Refreshing or navigating directly to `/itinerary` shows the same result regardless of what was requested (same root cause as the P0 above).

**Casey (Mobile User)**: The floating chat button and the fixed bottom action bar on `/itinerary` occupy the same bottom-right screen real estate with no mutual awareness, risking visual overlap on narrow phones. Star-rating touch targets on `/feedback` are ~38px combined width, just under the 44px minimum, making a mis-tap between adjacent stars easy for a distracted thumb.

## Minor Observations

- `Footer.tsx` uses a plain `<a href="#como">` while the rest of nav uses Next's `<Link>` — inconsistent but harmless for a same-page anchor.
- No `aria-live` region on the chat widget's message list — new replies aren't announced to screen readers.
- Heading levels skip (h1→h3, h2→h4) on `/`, `/home`, `/feedback` — should be sequential for screen-reader users navigating by heading.
- Font-size steps on `/itinerary` and `/feedback` are only 1.7:1 apart — a flatter type hierarchy than ideal.
