# Reglas de stack — Next.js 15 (App Router) + Tailwind
# Patrones que evitan escribir código que "se ve bien" pero rompe con este stack.

- App Router (carpeta src/app), NO pages router. Componentes son Server Components por
  defecto; agregar "use client" solo cuando se necesite estado/efectos/eventos del navegador.
- NUNCA importar funciones/módulos de servidor desde un componente cliente.
- Variables de entorno: solo las que empiezan con NEXT_PUBLIC_ llegan al navegador. TODO lo
  secreto (llaves, URLs de For3s, wallets) va SIN ese prefijo y se usa server-side.
- El cliente de For3s vive del lado del backend (apps/api/src/index.ts), NO en apps/web —
  este workspace no tiene ni debe tener un src/lib/for3s.ts propio. El frontend solo llama
  a NUESTRO backend (NEXT_PUBLIC_API_URL), nunca a For3s directo.
- Tailwind: usar los tokens del theme (bg, surface, ink, muted, primary, primary-deep,
  accent, accent-deep). No hardcodear hex sueltos — si necesitas una sombra/borde con alpha
  sobre `ink`, usa la custom property `--shadow-ink` definida en globals.css.
- Todo el copy de marca (textos, nav, testimonios, anfitriones, footer, chat) vive en
  apps/web/src/content/brand.ts — los componentes lo importan, no hardcodean strings. Este
  es el "punto único de marca": para duplicar el proyecto con otra identidad visual, este
  archivo + los hex de tailwind.config.ts + las imágenes de public/ son lo único que cambia.
- Imágenes: assets en public/ (hero-anfitrion.svg, anfitrion-*.svg — placeholders SVG).
- Antes de PR: `bun run build` en apps/web debe pasar. No commitear si el build falla.
